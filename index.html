Construction scheduling · browser-native

The schedule is the logic diagram.

SchedulePoint is a browser-based construction scheduling application built around a Time-Scaled Logic Diagram. Planners draw activities directly on a timeline and connect them with logic — rather than filling in a Gantt grid and hoping the network underneath is right.

A real CPM/GPM engine underneath: four dependency types with lag, calendars down to the working minute, constraints, progress, float, baselines and resources.

What SchedulePoint does

It is a scheduling tool for construction planners: build the programme, compute it properly, keep it honest as the job moves, and share it with the people who need to read it.

Build the programme graphically

Drop an activity onto the timeline, drag its width to set the duration, and pull a logic line to the next one. The network is what you are drawing — not a by-product of a table you filled in.

Compute it with a real engine

Forward and backward pass, total float, the critical path, driving logic, calendars, date constraints and out-of-sequence progress. The engine is measured against a P6-class conformance fixture, not asserted.

Run the job from it

Mark progress against a data date, snapshot a baseline and read the variance, log the reasons in notes, and hand the pen between planners with a clean single-editor lock.

  • 4dependency types (FS/SS/FF/SF) with lag
  • 7date constraint types honoured as labelled
  • 2,000activities per plan, the v1 scale target
  • <500msP95 recalculation at 500 activities

The gap it fills

Construction scheduling tools split into two camps. Heavyweight desktop applications — Primavera P6, MS Project — carry the licensing, the install and a Gantt-centric way of working. Lightweight web tools are Gantt-only and drop the underlying logic model altogether, which is the part that actually tells you why the job finishes when it finishes.

The graphical, network-first approach has a track record — Netpoint proved planners want it — but it stayed a desktop product. SchedulePoint is the browser-native version of that idea: the Time-Scaled Logic Diagram is first-class, the CPM/GPM implementation is correct rather than approximate, and a team can work on the same programme from a link.

The flagship surface

The Time-Scaled Logic Diagram

Activities sit where they happen in time, on lanes you control, joined by the logic that drives them. Everything else in the product is a projection of this.

Authoring

  • Draw an activity straight onto the timeline — click for the start, drag right for the duration.
  • Move it and the network re-flows live; successors follow, and the critical path re-highlights as you go.
  • Link two activities with a two-click link tool, choosing the dependency type and lag as you make it.
  • Lanes are yours — drag activities up and down, or let the auto-pack layout tidy the diagram for you.
  • Undo and redo across every edit — reposition, relane, create, delete, logic changes, hand placement.
  • Level-of-effort activities are composed by picking their start and finish drivers, not by typing dates.

Reading

  • Adaptive date ruler from year down to day, with zoom presets, pan and a marker on today.
  • Non-working days are shaded, so a bar that spans a shutdown looks like one.
  • Driving logic is visually distinct from non-driving — encoded by shape as well as colour, never colour alone.
  • Lenses dim what does not match: search and filter, colour by criticality or float bucket or WBS, and a ghost-bar baseline overlay.
  • Isolate a logic path to see only an activity's predecessor and successor chain — the full chain, or the driving one.
  • Next conflict steps through the plan's flagged activities and says in words why each is flagged.

Constraints appear as pins on the canvas. Logic lines route around bars rather than through them. The whole scene is drawn to a frame budget so panning a 2,000-activity plan stays smooth.

The scheduling capabilities

The CPM/GPM feature set construction planners actually use — not a reduced subset that falls over on a real programme.

The CPM engine

Forward and backward pass, total float, free float, the critical path and near-critical shading, with driving-logic tracking throughout. Choose whether "critical" means longest path or total float ≤ 0, and read total float as start, finish or the smaller of the two.

Dependencies

Finish-to-start, start-to-start, finish-to-finish and start-to-finish, each with lag in working or calendar time. Cycles are prevented rather than discovered later.

Calendars & working time

An organisation-level calendar library, a per-plan default and a per-activity override. Weekday patterns, dated exceptions and intraday shift patterns — the engine works in minutes, so a ten-hour shift is ten hours.

Date constraints

Start/finish no-earlier and no-later, must-start-on, must-finish-on and as-late-as-possible placement. A pin that breaks the logic is scheduled and flagged — never silently corrected behind your back.

Progress & the data date

Status, percent complete, actual dates, explicit remaining duration, and suspend/resume. Out-of-sequence work is handled by a plan-level mode: retained logic, progress override or actual dates.

Baselines & variance

Named snapshots with one active baseline per plan, working-day variance computed server-side, and the comparison shown in the table, on the canvas as ghost bars, and in the Gantt as a variance bar.

Resources

A resource library with assignments, per-assignment lag, a demand histogram and a canvas-aligned loading strip that stays under the diagram as you pan and zoom. Over-allocation is flagged on the bars.

WBS & activity types

Tasks, start and finish milestones, level-of-effort and WBS summary rollups. Membership is managed from the summary or in bulk from the list; dissolving a grouping removes the structure without removing the work.

Notes & audit

Attributed, time-ordered note threads on plans and activities for the weekly "why", plus an append-only audit log — enforced in the database, not just in application code — of who did what to which plan.

Ways to look at the same plan

One model underneath. Every view reads and writes the same activities, logic and dates.

The logic diagram

The primary editing surface, and where the programme is built. Time-scaled, lane based, live critical path, on-canvas labels.

Gantt

A grid-and-bar projection of the same model behind a TSLD | Gantt switch, with WBS summary rows, baseline variance bars and a printable programme. Read-primary by design — editing belongs on the canvas.

Float paths

Ranked driving chains into an activity you choose, with the relative float on each row — and the selected path emphasised in both the canvas and the Gantt.

Project explorer

A persistent, keyboard-navigable Client → Project → Plan rail with in-place create, rename and delete, deep-link reveal, and a recycle bin behind soft delete.

Built for a team, not a single seat

Construction scheduling is a team-of-teams activity. Work is scoped to organisations, and everyone gets the access their job needs.

Roles in SchedulePoint and what each can do
Role What they can do
Org admin Manage members, organisation settings, and the shared calendar and resource libraries.
Planner Full control of clients, projects, plans and activities. Holds the edit lock while building.
Contributor Update progress and add notes on assigned plans. Cannot alter logic or dates.
Viewer Read-only access to shared plans within the organisation.
External guest Read-only access to one plan via a revocable share link, with optional expiry. No account needed.

Many people can read a plan at once. Editing is a single-editor lock — the "pen" — with a clean hand-off, so two planners never quietly overwrite each other's logic.

Getting programmes in and out

Your schedule is your data. Bringing an existing programme across should not be a retyping exercise, and getting it out again should not need a support ticket.

Import

Read a Primavera P6 .xer or an MS Project MSPDI .xml into a new plan. The import runs as a dry run first and reports honestly before it commits: what mapped, what was approximated, what was repaired, what could not be carried across. Nothing is dropped silently.

Export

Schedule CSV (spreadsheet-safe), the diagram as PNG or PDF at whole-plan or current-view extents, a printable programme from the Gantt, and XER/MSPDI back out. An organisation admin can export the organisation's data on demand.

Who it is for

Planners & project controls

The primary user. Comfortable with WBS, logic, float and the critical path; in the schedule for hours at a time and expecting keyboard-speed tooling.

PMs & superintendents

Read the programme, mark progress, comment on what slipped. Need the picture to be readable without a scheduling background.

Clients & owners

Open a read-only link for status. No install, no licence, no account.

What it deliberately is not

The scope is stated as plainly as the features, because a scheduling tool that tries to be everything ends up trustworthy at nothing.

  • Not a general task tracker or PM board — no cards, no tickets.
  • Not an ERP or cost-control system — no invoicing, no earned value beyond schedule variance.
  • Not a document-management system — notes attach to entities, but drawings, RFIs and submittals live elsewhere.
  • Not a mobile-first field app in v1 — desktop and tablet planning is the target.
  • Not an attempt to replicate every corner of P6 — no risk analysis or Monte Carlo, and no coding-structure matrices.

Under the hood

A TypeScript monorepo, built to a consistent production bar — accessibility, tests and documentation are merge requirements rather than follow-ups.

The stack

  • Frontend — React, TypeScript, Vite, Tailwind CSS, Canvas 2D for the diagram
  • Backend — NestJS, a REST API documented with OpenAPI
  • Database — PostgreSQL via Prisma
  • Auth — self-hosted, with organisation-scoped RBAC
  • Delivery — Docker images built and published by CI

How correctness is held

  • A P6-class conformance fixture and capability matrix for the engine
  • A catalogue of seeded plans and hostile cases driven through the public REST API
  • End-to-end journeys in Playwright, per feature area
  • WCAG 2.2 AA as a merge requirement, on hand-rolled ARIA primitives
  • Architecture decisions recorded, including what was deliberately not built

Project status

SchedulePoint is substantially built and under active development: the engine, the canvas, the Gantt view, baselines, resources, interchange and the audit log have all shipped. It runs on Docker Compose, and the source is MIT-licensed and public.

A few terms, plainly

Time-Scaled Logic Diagram (TSLD)
Activities plotted horizontally by when they happen, joined by lines showing what drives what. The schedule as a network you can read at a glance.
CPM
Critical Path Method — the forward and backward pass that computes early and late dates and float from durations and logic.
GPM
Graphical Path Method — CPM's graphical successor, which treats the network diagram itself as the schedule rather than as a picture of one.
Total float
How long an activity can slip before it delays the project.
Data date
The "as-of" date for progress. Everything after it is rescheduled; everything before it is history.
Baseline
A frozen snapshot of the programme, kept to compare today's plan against.
